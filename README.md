# Cameyware 部署监控（CameywareBuildMonitor）

服务器上正在做什么，一目了然：上传和载入镜像、启动、健康检查、官网重建，以及 CMS 的部署和 GitHub Actions 的构建，预览站和正式站都有。

这个仓库只有**网页**（前端）。数据来自 cameyware_api 的 `services/build-monitor`（后端，`/ops/v1`），后端读取服务器上一个只看不改的小程序（agent）每 5 秒写下的快照。

## 怎么用

- 预览站：<https://preview.cameyware.com/ops/>（和预览站一样在 Cloudflare Access 后面），用官网的账号登录，网站管理员和超级管理员可以查看。
- 四个页签：**预览站**、**正式站**（部署按钮、正在进行的部署、每个项目的服务是否在线和版本、部署记录、从页面发起的部署）、**CMS 部署**、**GitHub 构建**。
- **从页面部署**（超级管理员）：在「预览站」页签按「部署到预览站」，确认后由部署电脑（CameywareServer 的 runner，登录时自动启动）用每个仓库已经提交的版本构建并部署，输出实时显示，可以停止。正式站要等正式站切换（S74.9）以后才开放。
- 有部署在进行时每 3 秒刷新，平时每 15 秒。

## 开发

| 命令            | 做什么                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------ |
| `npm run sync`  | 从官网复制配色、Mantine 主题和全局样式，从 cameyware_api 复制公司的地址（`src/generated`） |
| `npm run dev`   | 本机预览（端口 8813；`NEXT_PUBLIC_API_ROOT` 指向后端）                                     |
| `npm run build` | 静态导出到 `out/`（`/ops/` 下）                                                            |
| `npm run lint`  | 类型检查和格式检查                                                                         |

部署：在 `C:\CameywareCorpApps\server`（CameywareServer）运行 `npm run deploy:preview`，它会构建这个页面并放到预览站的 `/ops/`。

## 更新记录

### v0.9.0（2026-11-28）：并行部署时的进度

- **整体进度按最长的一条线算**：部署分两条线同时进行后，各类别的时间加起来会比整次部署长。现在「预计还要」等于剩下各类的通常耗时除以重叠程度（部署监控按最近几次同样部分的部署算出，第一次为 1），整体进度 = 已用时 ÷（已用时 + 预计还要）。
- **一个部分的那一步结束就算完成**，不再等后面有别的步骤开始（两条线同时跑时，另一条线可能还在构建）。健康检查仍然等整个部署结束才完成。
- 验证：类型检查、格式检查、构建；进度计算的测试 6 个（新增：重叠为 2 时预计还要减半）。

### v0.8.0（2026-11-28）：部署进度按类别显示

- **整体进度条**：正在进行的部署上方是一条动态的进度条。进度按时间算：已用时 ÷（已用时 + 剩下各部分的通常耗时）。旁边写着已用时、预计还要多久，以及正在做哪一步。
- **每个类别一个圆盘**：部署一开始就列出这次要经过的类别，每类一个圆盘：准备、每个要部署的部分（禄命秘解、账号服务、官网后端、CMS 后端……），以及健康检查（所有分组的启动和健康检查都归在这里）。还没开始的显示「等待」和通常耗时；进行中的按自己的耗时对比通常耗时走，到 95% 后停在那里等它结束；结束的显示「完成」或「失败」。构建新版本和重新部署（不用构建）的通常耗时分开算。
- **平滑变化**：进度条和圆盘每秒更新。某一类比预计早或晚结束时，数字会在几秒内慢慢调过去，不会一下子跳很多。
- **停止**：每个正在进行的部署卡片上都有「停止」（超级管理员可用），在终端里发起的部署也可以停止，由部署电脑上的 runner 结束它的进程；停止后在记录里标「已停止」。部署进行时，「部署到预览站」按钮下面写明正在部署、可以在下面停止。
- **步骤**：步骤列表收在卡片下方的「步骤」里。
- 验证：类型检查、格式检查、构建；进度计算的测试 6 个；浅色、深色和手机宽度下的截图，以及停止的确认框。

### v0.7.1（2026-11-27）：「通常」按部署的部分算

- **通常**：正在进行的部署只和以前部署同样部分的比（没有时和包含这些部分的比；都没有时不显示「通常」，进度按步骤算）。以前拿最近五次部署的中间值，分批部署以后会出现部署全部时「通常 38 秒」、圆盘停在 97% 的情况（要部署监控后端一起更新，CameywareServer v1.4.1）。
- **比通常多**：超过通常的时间后，不再只停在 97%，写明「比通常多」多久。
- 正在进行的部署写明这次部署哪些部分。
- 验证：类型检查、格式检查、构建；截图看过超时的部署卡片。

### v0.7.0（2026-11-27）：可以重新部署没变的部分，界面更紧凑

- **重新部署**：「不变」的部分也能勾选，勾上后标「重新部署」：版本不变，重新发送并重启它的服务（需要 CameywareServer v1.4.0）。都不变时按钮写明「要重新部署哪个，就勾上它」。
- **全选**：部分列表上方有「全选（已选 n/9）」，部分勾选时显示半选；有更新的部分时还有「只选有更新的」。
- **左右布局**：部署卡片顶部是部署电脑和按钮（不能按时原因写在按钮下面），下面左边是要部署的部分（宽屏每行两个，版本写在同一行），右边是各仓库的提交；手机上上下排列。
- **部署记录**：已经结束的部署一行显示：状态、进度百分比（完成 100%，失败显示做到了百分之几）、开始时间、总时长、部署人和电脑，不再画圆盘；「步骤」展开每一步。正在进行的部署还是圆盘。
- **内容更少**：「部署记录」和「从页面发起的部署」合成一个「记录」区，右上角切换；搜索框和筛选在同一行；从页面发起的部署每条一行，提交和输出在「输出」里展开；没有部署在进行时不再显示一张空卡片。
- 验证：类型检查、格式检查、构建；浅色、深色和手机宽度截图，全选、勾选不变的部分、确认对话框、展开步骤和两种记录都看过。

### v0.6.0（2026-11-27）：分批部署，只部署勾选的部分（禄命秘解 S84）

### v0.5.0（2026-11-27）：从页面部署（禄命秘解 S83）

- **部署**：「预览站」和「正式站」页签顶部新增「部署」卡片：部署电脑是否在线、它是哪台电脑、多久前上报；每个仓库将要部署的提交（提交号、说明、多久前提交、是否已推送到 GitHub、有几个文件没提交——没提交的不会部署）。

- **从页面发起的部署**：新的记录列表，分页、按状态筛选（各有数量）、按部署人、电脑、仓库或提交搜索；每条可以展开看输出。记录不能删除（保留 90 天）。
